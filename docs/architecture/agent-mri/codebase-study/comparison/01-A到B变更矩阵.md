## 关键解释

### UI 页面与主任务流

- **VERIFIED FACT**：A/B0/B1 都是固定 dashboard；13 页只在 B2 出现。
- **VERIFIED FACT**：`4207800` 的 13 页是静态展示原型；`91343be` 才有 Mock 状态、timer、QC、包和历史。
- **INFERENCE（高置信）**：页面数量增加不等于状态真值自然形成，当前页号、控件草稿和 `MockWorkflow` 仍是多个所有者。

### DLL/SDK/代理边界

- 原生 SDK：Qt 直接加载 DLL，控制设备并监听状态。
- runtime：给原生 SDK 链提供已校验的 DLL/config/par；只在 c77 分支。
- proxy：Qt 调用外部 Python 黑盒入口并接收工件；不是 DLL 替换。
- 当前 Mock：不使用上述两条采集链，但二进制源码仍保留真实旁路。

### 数据与证据

- A/B0 没有稳定 run/snapshot/结果包。
- B1-P 有外部 task ID/文件路径/hash 日志，但没有原子结果事务。
- B2 当前结果包只证明 Mock PNG/QC/参数/审计的内部一致性，不能证明真实 RAW 或实机成像。
