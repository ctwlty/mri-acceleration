# Comparison｜03 补丁耦合与技术债地图

本页记录 As-Is 耦合和证据缺口，不提出重构方案。

## 1. 高层依赖地图

```text
main.cpp
  ├─ CLI：Mock QA / native SDK / eggcontroller 配置
  └─ MainWindow
       ├─ UI 构造、01–13 路由、控件草稿
       ├─ Mock timer 与应用编排
       ├─ MockWorkflow（领域状态）
       ├─ ImageQualityEvaluator / MockResultPackage（同步文件副作用）
       ├─ DeviceBridge → MriSdkLoader → DLL（真实旁路）
       └─ EggControllerProcess → QProcess（当前无 start 边）
```

## 2. 耦合项

| 耦合/重复 | VERIFIED FACT | 可能影响（INFERENCE） | 证据位置 |
|---|---|---|---|
| `MainWindow` 横跨 UI/路由/编排/文件/设备 | 直接拥有并调用 Mock、QC、package、SDK、process | 改按钮可能同时改变页面与领域状态；测试组合成本高 | `91343be:client/src/app/MainWindow.cpp` |
| 页面号与领域状态双轨 | `setWorkflowStep` 不校验 MockWorkflowState | QA 跳页/返回可显示不一致状态 | `::setWorkflowStep/setMockWorkflowStep` |
| 页面草稿与确认布尔分散 | 控件、3 个布尔、`MockWorkflow` 各持一部分 | 看起来已选择但 Next 不可用；旧 run 状态归属不清 | `::currentMockDraft/refreshWorkflow` |
| 模板两套选择源 | 左栏 list UserRole 与页 02 radio 分离 | 外观与 enabled 逻辑可能分裂 | `91343be:client/src/app/MainWindow.cpp:1428-1519,4460-4478` |
| 三层 action 代理 | 页内 CTA、全局 Next、左栏控制通过 objectName click | 映射漏更新时形成“死按钮”或文案不一致 | `buildCenterPane/refreshWorkflow/refreshMockWorkflowUi` |
| 旧页面代码留存 | legacy page/right builder 无活动调用 | 阅读/修改时容易改错非活动路径；二进制膨胀 | `makeLegacyWorkflowPage/buildLegacyRightPane` |
| SDK 安全能力分叉 | c77 runtime gate 不在 current | 当前产品代码与历史实机安全结论错配 | Git merge-base 与文件不存在证据 |
| proxy 代码与生产调用边分离 | current 有 config/class/script，无 `start` | 配置看似可用但实际不会运行；测试易只测协议 | `configureEggController`、git grep |
| proxy 与仓内旧 UI 契约不一致 | proxy 要 `demoCheckbox`，提交 UI 无此属性；HCController 导入 mock | fake 测试通过不能证明外部真实入口 | `8e4ad0b:client/tools/eggcontroller_proxy.py::run_once`、`8e4ad0b:eggcontrollerV2/Iface/HCController.py`、`8e4ad0b:eggcontrollerV2/MainWindow_V3.py` |
| 真实与 Mock 入口同一构建面 | CLI auto-connect/verifier 与 Mock GUI 同源码/CMake | “默认不触发”与“发行物不含副作用入口”容易混淆 | `91343be:client/src/main.cpp`、`91343be:client/CMakeLists.txt` |
| 结果状态双写 | package writer 与 workflow 都记录保存事件/状态 | 内存审计和磁盘审计顺序可能不完全同源 | `MockResultPackage::write`、`MockWorkflow::markPackaged` |
| 历史入口依赖内存 Packaged | 磁盘可能有 manifest，但正常 UI 需当前 run Packaged 才开放 | 重启后已有历史可能不可发现 | `refreshMockWorkflowUi/loadMockHistory` |
| 同步 QC/写包/历史 verify | 都在 GUI 线程，无 timeout/cancel | 数据增长时可能冻结 UI | `completeMockProcessing/save/loadHistory` |
| 失败阶段未建模 | 任意有 identity 的 Failed 可 retry Processing | 采集阶段失败与处理阶段失败语义混合 | `MockWorkflow::fail/retryProcessing` |

## 3. 分支补丁耦合

### native SDK 主干

严格 loader、校准调用、会话状态机、真实 UI 接入、超时/RAW 判定分散在 `7a4a4d3` 到 `c236e00` 的多个提交。`c236e00` 是可复现基线，而不是“一次性 SDK 重写提交”。

### runtime 支线

`c77aeb4` 在 bridge/MainWindow 外围同时加入 runtime resolver、identity proof、precheck ticket 和 baseline gate；当前产品分支没有这些提交。任何只 cherry-pick UI 或 manifest 的叙述都会漏掉跨层契约。

### proxy/Mock 支线

`8e4ad0b` 曾把 Start 接到 proxy；`4207800` 为形成 Mock 13页而 HOLD 并移除 start；随后 `91343be` 又在相同 MainWindow 中加入 Mock state/package。结果是类型/CLI/测试资产仍在，生产调用边消失。

## 4. 数据与身份债务

| 身份 | 当前来源 | 断点 |
|---|---|---|
| template | catalog index/字符串 | 无跨版本稳定 ID；index 0 被当可运行 Mock 基线 |
| task | UI 文案/结果包字段 | 无独立 Task 仓库 |
| run/snapshot | MockWorkflow UUID | 只对 Mock 成功包持久化 |
| SDK runtime | c77 manifest | 当前分支缺失；外部 PTScan 已漂移 |
| proxy task | 外部 register record | 无不可变 egg-root/source hash 绑定 |
| RAW/图像 | proxy 协议期望返回路径，或 SDK `rawFileReady` | 当前 Mock 包不接这两条链；proxy 仓内真实入口有断点 |
| software commit | CMake 注入 | dirty tree/resource/发布 EXE 未统一绑定 |

## 5. 测试债务

- 全控件可观察行为测试提前返回；其后的断言不执行。
- automation GUI 测试被 `#if 0`；fake process/proxy 仍不能证明真实 legacy UI 契约。
- 各分支测试数量不同，且没有本轮新鲜执行；历史全绿结论不能横跨分支。
- 没有一个证据 manifest 把 source commit、build、CTest、截图、发布 EXE 和外部资产身份绑定为一次验收。
