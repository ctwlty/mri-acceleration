## 3. 导航和按钮机制

当前存在三层入口：页内 canonical CTA、底部 `WorkflowNextButton`、左栏 Mock 控制。底部/左栏经 `findChild(objectName)` 找 canonical 按钮并调用 `click()`；enabled/text 映射则分别分布在 `buildCenterPane()`、`refreshWorkflow()`、`refreshMockWorkflowUi()`。

- **VERIFIED FACT**：这是按钮代理，不是一个统一 action registry。
- **VERIFIED FACT**：第 12 页是两阶段动作：先页内 Save，随后全局 Next 所代理的 History 才启用。全局 Next 不代理 Save。证据：`91343be:client/src/app/MainWindow.cpp:1255-1259,4104-4128,4252-4269,4425-4430`。
- **VERIFIED FACT**：第 2 页中间默认 radio 与左栏 `sceneList` 是两套选择状态；Next 的 enabled 依赖左栏 `Qt::UserRole == 0`，不是 radio 的选中外观。证据：`MainWindow.cpp:1428-1519,4460-4478`。
- **INFERENCE（高置信）**：两套状态源与三处分散 action 映射可以解释“卡片看起来已选但下一步不可用”“页内和全局按钮反馈不一致”的机制；没有本轮点击轨迹时，不能声称它是某一现场截图的唯一根因。

## 4. 页面状态与可见反馈

| 状态 | 当前表达 |
|---|---|
| Loading | 主要通过进度条/状态标签；无统一页面级模型 |
| Empty | MockWorkflow Empty；10–13 页应隐藏图像/QC/结果动作，但 QA 跳页可直接进入空页 |
| Ready | 页面草稿和三个 `MainWindow` 确认布尔共同决定 |
| Warning/Error | `AutomationStatusLabel`、卡片/提示文本；无统一 error object |
| Disconnected | 真实控制区显示 HOLD/未加载；与 Mock 页面状态并行 |
| Permission denied | 没有用户权限模型；不可用行为多用 disabled + 原因文本 |
