## 当前默认启动链

```text
main
  → QApplication / app.qss
  → 解析 CLI
  → MainWindow
      → DeviceBridge + MriSdkLoader（仅构造，不 load）
      → EggControllerProcess（仅构造，不 start）
      → MockWorkflow（Empty）
      → 左栏 + 13页中心栈 + 13页右栈 + Mock timer
  → 可选 --mock-step：仅跳 QA 页面
  → 可选 automation 参数：只保存代理配置
  → 可选 --auto-connect：显式进入真实 DLL load/init
  → show / exec
```

- **VERIFIED FACT**：无参数启动不加载 SDK、不启动 eggcontroller、不调用 Run/Abort。
- **VERIFIED FACT**：`--auto-connect` 仍是可达的真实副作用入口；当前 GUI 的 HOLD 不等于二进制完全不含真实入口。证据：`91343be:client/src/main.cpp:111-136`、`MainWindow.cpp::loadSdkAndConnect`。
- **VERIFIED FACT**：automation 参数在当前只调用 `MainWindow::configureEggController`；生产 `client/src` 中没有 `m_eggController->start(...)`。证据：`91343be:client/src/app/MainWindow.cpp:914-920`。

## 构建、部署与运行时差异

### B0

- `mri_sdk_verify` 可独立 load/init，显式 `--scan` 才进入扫描。
- `client/scripts/build.ps1` 与 `deploy.ps1` 在原生 SDK 演进中建立 Windows 构建/Qt 部署流程。
- 发布目录包含 GUI/verifier/Qt runtime，但本阶段没有固定 SDK 资产身份清单。

### B1-R（仅 runtime 分支）

- `stage_mri_runtime`/`stage-mri-runtime.ps1` 把外部 DLL、`hw_cfg`、参数文件复制到 `mri-runtime/`。
- `MriRuntimeResolver` 校验 manifest、路径、哈希和 `hw_cfg` 清单，并产生 identity proof。
- **VERIFIED FACT**：这些文件不在当前 `33be` 提交树；不能把 B1-R 的发布安全面写成当前能力。

### B1-P/B2（当前祖先线）

- `8e4ad0b` 部署 proxy 脚本，但不携带 Python 环境、外部 eggcontroller 根目录、DLL、`hw_cfg` 或 PTScan。
- 当前 CMake 仍同时构建 Mock GUI、真实 SDK adapter/verifier 和代理代码。
- **INFERENCE（高置信）**：当前发布物是多运行模式代码的组合，而不是物理隔离的 Mock-only 二进制；默认 UI 安全与发布物副作用面是两个不同命题。

## 错误、超时与关闭

- CLI 参数非法：返回非零；auto-connect 失败写 `qCritical`，窗口/事件循环仍可能存在。
- 单次 DLL 函数调用无调用级 timeout。
- DeviceBridge 的扫描/停止/RAW settle 有外层 timer/超时；详见 [业务流程与状态](./03-业务流程与状态.md)。
- `EggControllerProcess` 使用异步 `QProcess`，但在 `8e4ad0b` 没有总 timeout、取消或 kill 契约。
- 当前 `closeEvent` 只针对正在运行的 eggcontroller 进程；没有对 Running/Paused Mock 状态做关闭保护。证据：`91343be:client/src/app/MainWindow.cpp:923-930`。
