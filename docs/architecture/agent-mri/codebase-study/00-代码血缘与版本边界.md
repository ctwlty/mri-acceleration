## 5. “替换/接入 DLL 等”的准确拆分

“替换 DLL”不是一个单一代码动作，现有证据显示至少三层不同含义：

1. **B0：原生 Qt 动态加载重写。** `MriSdkLoader` 从 A 的宽松 `LoadLibraryA`/Demo fallback，演进为 `LoadLibraryW`、严格导出绑定、类型化错误和设备状态机。这是适配代码的修正，不是把 DLL 二进制提交进 Git。
2. **B1-R：运行时资产部署与身份绑定。** `c77aeb4` 用 `mri-runtime-manifest.json` 和 `stage-mri-runtime.ps1` 从外部已验证目录复制 `mridll.dll`、`hw_cfg`、`PTScan.par`，并校验哈希。资产仍被 Git 忽略。
3. **B1-P：自动化程序进程代理。** `8e4ad0b` 不是直接替换 `mridll.dll`，而是 Qt 通过 `QProcess` 启动 Python proxy；协议意图是调用外部 eggcontrollerV2 的一次入口并返回三类工件路径。是否加载 DLL、加载哪份 DLL 以及能否产出工件，均由未绑定的外部 `egg-root` 代码/资产决定。该提交树自身的 legacy UI 缺少 proxy 强制访问的 `demoCheckbox`，且 `HCController.py` 导入 `console_mock`，所以不能把协议意图写成仓内真实链已经可运行。

**VERIFIED FACT**：当前 `33be` 包含第 1 层和第 3 层的源码，但不包含第 2 层的 `MriRuntimeResolver`、runtime manifest 或 staging script；并且当前生产 UI 中没有 `m_eggController->start(...)` 调用。
