## 启动调用链

```text
main()
  → QApplication
  → 读取 :/app.qss（失败时静默使用空样式）
  → MainWindow
      → DeviceBridge
      → SceneCatalog::defaults()（7 个模板）
      → Header / 左中右三栏 / Footer
      → 构造函数内联 connect(...) 连接各控件/bridge 信号
      → DeviceBridge::loadSdk("")
          → MriSdkLoader::load("") → Demo
      → DeviceBridge::initialize(...)
          → Demo 计数清零
      → 默认选择第一场景、对象、模板
  → show()
  → QApplication::exec()
```

证据：`80b5d85:client/src/main.cpp:6-25`、`80b5d85:client/src/app/MainWindow.cpp:58-105`、`80b5d85:client/src/app/MriSdkLoader.cpp:21-29,107-115`。

## 执行模型

- **VERIFIED FACT**：没有 CLI 参数、环境运行模式、第二入口、线程池、`QProcess` 或 `QTimer`。
- **VERIFIED FACT**：默认启动不加载 DLL、不写 DRY_RUN、不调用 Run/Abort；所有默认状态只在内存中创建。
- **VERIFIED FACT**：点击“加载 SDK”会在 GUI 线程同步选择 DLL、调用 `loadSdk()`，成功后立即执行 `initialize()`。证据：`80b5d85:client/src/app/MainWindow.cpp:653-672`。
- **INFERENCE（高置信）**：A 是“单窗口演示骨架，附带真实 DLL 控制钩子”，不是可独立部署的完整发行物；缺少 Qt runtime 部署、SDK 资产布局、版本清单和目标 Windows 验收。

## 路径与部署缺口

构造器设置的路径为：

- init：`Iface/mriRely/hw_cfg/init.ini`
- 输出：`demo_output`
- 参数：`Iface/mriRely/par0423.par`

证据：`80b5d85:client/src/app/MainWindow.cpp:88-105`。

**VERIFIED FACT**：提交树内实际 SDK 相关文件位于 `eggcontrollerV2/Iface/mriRely/...`，其中包括 `eggcontrollerV2/Iface/mriRely/par0423.par`；Qt 使用的却是无 `eggcontrollerV2/` 前缀的 `Iface/mriRely/par0423.par`。因此缺失的是与 Qt 默认工作目录相匹配的路径，而不是仓库内完全没有该参数文件。这些文件也没有进入 QRC。

**INFERENCE（高置信）**：真实模式是否能找到配置取决于进程工作目录和外部未跟踪文件，源码没有稳定部署契约。

## 错误与恢复

- 样式文件打不开：静默继续。
- DLL 路径为空：进入 Demo。
- Windows DLL 缺失或导出绑定失败：回退 Demo，`load()` 仍返回 `true`；错误仅通过状态字符串旁路暴露。
- Init 任一步失败：返回 false，但 loader 仍处于 Real mode；没有统一 rollback/Fault 状态。
- **UNKNOWN**：A 在当前 Windows/Qt 版本上能否新鲜构建运行；本轮没有执行构建。
