## 4. 取证规则

### 4.1 VERIFIED FACT

只有以下内容可标事实：

- 当前 HEAD 源码中可定位的控制流、数据结构和调用点；
- CMake/脚本中明确声明的构建或部署行为；
- 已有日志或 manifest 中明确记录、且能说明其提交绑定范围的内容。

“测试函数存在”只证明断言存在，不证明本轮通过。未运行当前 HEAD 的测试，因此本目录不写“HEAD 测试全绿”。

### 4.2 INFERENCE

推断必须同时给出支撑事实和置信度。例如：

- **高置信 INFERENCE**：重启后即使磁盘已有结果包，正常 UI 仍无法直接进入历史，因为
  `OpenHistoryButton` 的门禁依赖当前内存 `MockWorkflowState::Packaged`，而启动后模型为 Empty
  （`MainWindow.cpp:4115-4128`；`MockWorkflow.h:185` 的默认状态；`MainWindow.h:199` 的默认构造成员）。
- **中置信 INFERENCE**：巨型 `MainWindow` 会放大状态同步成本；这是结构判断，不是已发生故障的运行证明。

### 4.3 OPEN DECISION

源码能回答的问题不进入决策树。只有会改变发布边界、领域真值或事务/恢复语义的选择，才进入
[06-待 Grill 决策树](./06-待Grill决策树.md)。
