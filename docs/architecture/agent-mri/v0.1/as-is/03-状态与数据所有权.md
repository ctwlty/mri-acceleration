## 2. 页面状态与领域状态的双源

### VERIFIED FACT

- `setWorkflowStep()` 可以在不改变 `MockWorkflowState` 的情况下跳页
  （`MainWindow.cpp:4273-4354`）。
- `setMockWorkflowStep()` 更会先重建 Empty workflow，再开任意页（`:4356-4363`）。
- `refreshWorkflow()` 先按页面号生成状态条（`:4365-4397`）；
  `refreshMockWorkflowUi()` 再按领域状态覆盖 10–12 页部分内容（`:3985-4270`）。
- 运行活跃和执行完成由 UI bool 控制多个按钮/图像，而领域模型另有 Running/Paused/Processing。

### 一致性风险

| 场景 | 当前机制 | 风险判断 |
|---|---|---|
| `--mock-step 11` | 模型先重置 Empty，再显示 11 | 有意 QA 空态；若生产逻辑只看页号会误判成功 |
| 10→8 Back | 只换页；Processing run 仍在内存 | 下一次 start 用新 candidate 覆盖旧 run，无明确放弃审计 |
| 11→7 Back | 只换页；QcReady run 仍在内存 | 重新规划与旧结果并存，直到下一次 start 覆盖 |
| 离开 09 | 停 timer、清 `m_mockRunActive`，不调用 `MockWorkflow::cancel()` | 程序化跳页可留下 Running/Paused 模型；正常 UI Back 在活跃时禁用 |
| 关闭窗口 | `closeEvent()` 只阻止 eggcontroller 运行，不检查 Mock | Running/Paused 内存 run 可随窗口销毁且没有持久取消审计 |
| 修改场景/搜索 | 可能 `applyScene()` 重置 workflow | 已封存包仍在磁盘，但内存 Packaged 和历史入口消失 |

前三项控制流是 VERIFIED FACT；“可能造成用户感知结果消失/伪成功”是高置信 INFERENCE，未做本轮运行验证。

## 3. 任务、模板、方案、run、snapshot 的真实模型

### 3.1 Task

- 仓库没有 `Task` 类型或稳定 task ID。
- UI 用场景/对象、固定 `WATER-PHANTOM-001`、模板、三个确认布尔共同表达“当前任务”。
- `currentMockDraft()` 在点击开始时才把这些值物化（`MainWindow.cpp:3549-3623`）。
- `task-note.txt` 是固定说明，不是独立任务实体。

### 3.2 Template

- `SceneTemplate` 是展示字段组成的字符串 DTO，没有 template ID（`SceneTemplate.h:5-34`）。
- `SceneCatalog::defaults()` 编译进程序，不可在 UI 保存新版本。
- 快照中的 `templateId=water-phantom-axial-v1` 和模板名由 `currentMockDraft()` 硬编码，
  并非从 `SceneTemplate` 读取（`MainWindow.cpp:3554-3556`）。
- 可运行门禁依赖 `QListWidgetItem::UserRole == 0`，即 catalog 排序，而非稳定 ID。

### 3.3 Plan / Protocol Draft

- 没有独立 `Plan` 聚合或版本仓库。
- L2 值在 QLineEdit；L3 是展示/展开；定位几何在自定义 QWidget；对照标志在 MainWindow。
- “另存版本”明确禁用；当前 DRY_RUN handler 只显示提示，没有调用已有文件生成器
  （`MainWindow.cpp:1838-1848,5465-5472`）。

### 3.4 Run / Snapshot

- `MockWorkflow::start()` 才生成新的非空 run/snapshot ID 并复制 draft（`MockWorkflow.cpp:326-358`）。
- snapshot 从这一刻冻结；开始前没有可引用的 snapshot ID。
- 默认随机 UUID 提供概率唯一性，但没有结果根跨进程锁、冲突占用协议或唯一 Run owner。

### 3.5 Result / History

- 标准 PNG bytes 留在 MainWindow，hash/QC 留在 MockWorkflow，直到第 12 页写包。
- 成功包之后，目录 + manifest 成为历史真值。
- `loadHistory()` 每次扫描文件系统，不保留索引、缓存或 task/run repository。

## 5. 持久化和事务边界

### 成功路径

1. `MockResultPackage::write()` 验证输入。
2. 拒绝已有 `root/runId`。
3. 创建同一 root 下 `.runId.staging-UUID`。
4. 逐个 `QSaveFile` 写 6 工件并回读 size/hash。
5. 写 manifest。
6. `rename(staging, runId)`。
7. 返回成功后，`MainWindow` 再调用 `MockWorkflow::markPackaged()`。

证据：`MockResultPackage.cpp:197-335`、`MainWindow.cpp:3838-3850`。

### 分裂点

- writer 在磁盘 audit 中自己合成 `PACKAGE_SAVED`（`MockResultPackage.cpp:259-272`）。
- `markPackaged()` 再在内存 audit 追加另一个 `PACKAGE_SAVED`（`MockWorkflow.cpp:506-517`）。
- 如果磁盘 write 成功而内存 mark 失败，包已存在但 UI 不一定进入 Packaged。当前调用参数下难触发，
  但事务所有权确实跨两个对象。
- Cancelled 没有独立磁盘事件；Failed 若随后重试成功并封存，既有失败审计会进入包。未恢复、未封存的 Failed run 与 Cancelled run 在退出后都丢失。

## 6. 重置与继承

`resetMockWorkflow()` 只重建 workflow、清 PNG/运行 bool/timer（`MainWindow.cpp:3656-3664`）。
`applyScene()` 另外清三个确认（`:5717-5723`），但以下状态不在两者中统一复位：

- `m_comparisonEnabled`；
- L2 编辑器内容；
- LocalizationPlannerView 几何/成像目标；
- 历史表格临时投影。

下一次 `currentMockDraft()` 会再次读取这些 UI 值。于是“新任务”当前既可能是清空 run，也可能继承旧方案草稿，
代码没有显式的“新建空任务”与“基于当前方案复制”两个命令。

## 7. As-Is 所有权结论

- **VERIFIED FACT**：`MockWorkflow` 是 run/snapshot/QC 元数据的领域所有者，但不是页面、草稿、PNG bytes、计时和包事务的唯一所有者。
- **VERIFIED FACT**：封存历史的最终真值是文件系统，不是当前内存 workflow。
- **INFERENCE（高置信）**：To-Be 若继续让页面号、UI 布尔和领域状态并列为真值，按钮与结束态问题会继续以不同形式复现。
- 下一步必须先回答发布边界，再决定生产路由是否完全从领域状态派生；见
  [06-待 Grill 决策树](./06-待Grill决策树.md)。
