# 04｜接口与副作用边界

## 1. 边界结论

- **VERIFIED FACT**：默认无参数 GUI 的可见 Mock 链静态不可达真实 SDK、连接、Run 和 Abort。
- **VERIFIED FACT**：源码和当前部署脚本仍交付可达真实副作用的 CLI/public API/验证器。
- **VERIFIED FACT**：eggcontroller 代理在生产 GUI 中没有启动边，但代理一旦被直接调用会关闭 demo 并执行旧程序的一次同步采集。
- **INFERENCE（高置信）**：当前安全边界是“默认交互约定”，不是“发布物能力隔离”。

## 3. 默认 GUI 为何保持 HOLD

### 可见控制

- 控制模式 combo 只有 `mock` 且禁用（`MainWindow.cpp:1044-1063`）。
- 加载 SDK、连接、真实预检、真实 Run、Abort 控件禁用/隐藏并带 LIVE BLOCKED 原因
  （`:1069-1126`）。
- `handleConnect/handleLoadSdk/handlePrecheck` 在旧代码前无条件返回（`:5418-5462`）。
- `handleStart/handleAbort` 只记 HOLD（`:5474-5477,5527-5530`）。
- `updateSessionState/updateControlMode` 不按 Ready 放行，始终禁用（`:5605-5638`）。

### Mock 行为

- `startMockRun()` 只创建 `MockWorkflow` candidate（`:3666-3715`）。
- 处理只读 `:/mock-reconstruction.png`，没有 RAW 或 SDK 输入（`:3718-3804`）。
- 三项开始确认之一明确要求“不触发 SDK、设备、Run 或 Abort”；领域也只允许 `DataSourceKind::Mock`
  无阻断（`MockWorkflow.cpp:194-209,541-558`）。

## 4. 为什么不能称为“发布物物理 Mock-only”

### 4.1 `--auto-connect`

`main()` 显式接受真实路径并在 event loop 开始时加载 DLL，并尝试执行 SDK 初始化、配置、校准与状态查询。
它不自动 Run；源码把成功返回后的内部会话置为 Ready，但该调用链没有独立的物理连接成功门禁，因而不能仅据此证明设备已物理连接。
参数校验没有禁止它与 `--mock-step` 组合，所以页面可能显示 Mock/Empty，而底层会话已经 Ready。

### 4.2 公开 API

`MainWindow::loadSdkAndConnect` 是 public；`test_main_window.cpp:136-154` 用 fake SDK 直接证明它可达。
这不是 UI 按钮路径，但属于交付代码能力。

### 4.3 独立验证器

`mri_sdk_verify` 无 `--scan` 也会加载/初始化；带 `--scan` 会真实 Run。`deploy.ps1` 默认复制它。

### 4.4 休眠 automation

生产 GUI 只配置、不启动 `EggControllerProcess`。但部署脚本复制 `eggcontroller_proxy.py`，而该脚本内部是非 demo
的一次采集入口。它是休眠的真实副作用资产，不是 Mock 资产。

当前活动布局也没有调用 `makeReconstructionViewport()`；`m_kspaceImageView/m_finalImageView` 默认是 null，
只在该未调用 builder 中赋值（`MainWindow.h:150-151`、`MainWindow.cpp:5090-5123`）。而
`showEggControllerArtifacts()` 在成功回调中直接解引用两者（`:5660-5663`）。因此如果只把
`EggControllerProcess::start()` 接回而不调整活动布局，完成回调存在空指针风险；这进一步证明 automation
不是“已集成但隐藏”的生产链。

## 5. SDK 层的实际防线与缺口

### 已实现

- `MriSdkLoader::load` 不会在 DLL 失败时回退 Demo；必须绑定所有必需导出
  （`MriSdkLoader.cpp:22-51,429-469`）。
- `DeviceBridge::startScan` 要求会话 Ready，再 `prepareScan`，Run 返回 0 后进入轮询
  （`DeviceBridge.cpp:133-160`）。
- 异常 ScanStatus `-1/5/6` 或扫描超时会 Abort（`:236-278`）。
- 完成后要求输出目录出现新增或 `size + mtime` 元数据指纹变化的非空 `*.raw`（`:246-268,358-386`）。
- Abort 有单次防重（`MriSdkLoader.cpp:376-388`）。

### 未实现为生产门禁

- DLL SHA/版本/签名；
- 设备唯一身份与连接码语义验证；
- 启动前 IDLE 业务门禁；
- 场景/横断位到参数文件的已验证映射；
- 参数 snapshot 与真实 Run 绑定；
- 隔离输出目录和输出前缀归属；
- 跨进程唯一 Run owner；
- 本次单次 Run 人工授权。

`MockWorkflow::executionBlockReasons()` 列出了这些 Live 门禁（`MockWorkflow.cpp:550-557`），但它只是
Mock 领域中的 BLOCKED 文案；没有包裹 `DeviceBridge::startScan()`。

### 其他危险遗留

- `MriSdkLoader::prepareForScene` 忽略 `scene`，硬编码参数并写 `scenario_nmr.par`，当前无调用、无测试
  （`MriSdkLoader.cpp:335-357`）。
- `DeviceActionAvailability` 把 Ready 映射为 canRun，但生产 UI 不使用，只有测试调用
  （`DeviceActionAvailability.cpp:3-20`）。
- `client/README.md:33-56` 仍描述 GUI 可扫描/急停，与当前永久 HOLD UI 不一致。

## 6. 异步、超时和取消边界

### DeviceBridge/MriSdkLoader

- `LoadLibraryW`、Init、Config、校准、Run、Abort、状态查询均同步在调用线程；单次调用没有 watchdog。
- Run 返回后，DeviceBridge QTimer 才负责扫描超时、停止超时和 RAW settle 超时
  （`MriSdkTypes.h:48-58`、`DeviceBridge.cpp:195-278`）。
- 析构 `shutdown()` 在仍扫描/停止时可能 Abort 一次再 CloseSys（`MriSdkLoader.cpp:255-271`）。

### EggControllerProcess

- QProcess 异步读取 stdout/stderr，按行解析 JSON（`EggControllerProcess.cpp:23-138`）。
- 没有启动/总时长 timeout、取消、terminate 或 kill 接口。
- `closeEvent()` 只在该进程运行时阻止窗口关闭（`MainWindow.cpp:923-930`）。

### 文件系统

- Mock 可写性“检查”会创建结果根和临时探针（`MainWindow.cpp:3626-3653`）。
- 写包失败会尝试 `removeRecursively()` staging，但忽略清理返回值（`MockResultPackage.cpp:225-237`）。
- verify/loadHistory 会同步把工件读入内存并哈希，无取消、大小上限或历史分页。

## 7. 来源绑定边界

### Mock

- QRC PNG bytes → SHA-256/size → reconstruction metadata；QC 的 image hash 必须一致。
- manifest 再记录六项工件 size/hash，并交叉检查 run/snapshot/source/QC/audit。
- `softwareCommit` 只要求非空；不校验 40 位 Git hash，不记录 dirty tree 或资源树身份。
- manifest 无签名/外部可信摘要，因此适合偶发损坏检测，不是恶意防篡改证明。

### DeviceBridge RAW

- RAW 只按路径、size、mtime 相对扫描前变化判定；允许同名覆盖。
- 不绑定 run/snapshot、hash、输出前缀或协议身份。

### Eggcontroller artifacts

- 两张图要求同一 task-ID 目录和固定文件名；RAW 只要求绝对、存在、非空。
- RAW 未与 task ID、两图目录或 SHA-256 绑定（`EggControllerProcess.cpp:140-178`）。
