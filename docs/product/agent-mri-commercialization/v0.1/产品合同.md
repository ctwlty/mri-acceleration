# Agent-MRI 科研工业商用化优化产品合同 v0.1

## 1. 产品定位

本版本把现有“场景化核磁共振控制台”收敛为一条可验证、可审计、不会触发真实设备副作用的科研 Mock 任务闭环。它用于证明从任务选择到结果包留存的产品行为、数据来源和证据边界能够一致运行，不用于证明真实 MRI 采集能力。

### 非目标

- 不加载或替换真实 `mridll.dll`，不连接设备，不调用 Run、Abort 或 eggcontrollerV2。
- 不把历史 RAW、示例图片或预置数值表述为本次真实采集。
- 不新增重建算法，不分析厂家内部链路，不修改协议参数文件。
- 不扩展临床诊断、医疗器械法规、多用户权限、远程协作或云端发布。
- 不重做三栏布局和 01–13 页面视觉合同。

## 2. 用户与角色

| 角色 | 本版本职责 | 权限边界 |
|---|---|---|
| 科研操作者 | 选择水模场景、确认模板、完成 Mock 预检、执行 Mock、查看 QC、保存结果包 | 只能运行 `MOCK`；不能触发 Live |
| 科研复核者 | 查看结果、QC、来源记录和历史结果包 | QC 为软件提示，最终科研判断由人完成 |
| 开发/验收人员 | 运行自动化测试、检查 manifest、截图和审计事件 | 不得将测试或 Mock 证据升级为实机证据 |
| 现场设备负责人 | 未来确认线圈、水模、设备空闲和单次 Run 授权 | 本版本没有任何现场动作入口 |

## 3. 权威真值

1. 本合同、`页面合同/01.md` 至 `13.md`、`验收合同.md` 是 v0.1 产品行为真值。
2. `MockWorkflow` 是一次运行的状态、来源、run ID、snapshot ID 和审计事件真值。
3. 封存结果包的 `manifest.json` 是已生成工件的路径、大小、SHA-256 和来源真值。
4. `MainWindow` 只展示模型和结果包已证实的数据；不得以页面编号推定成功状态。
5. 真实设备状态在没有真实、同次、可追溯证据时一律为 `BLOCKED` 或 `unknown`，不得用 Mock 状态替代。

## 4. 核心产品合同

### 数据源

`DataSourceKind` 只有三种：

- `Mock`：本版本唯一可执行数据源，所有界面、审计、manifest 与工件均显式标记 `MOCK`。
- `HistoricalRaw`：本版本不可运行，显示“历史 RAW 尚未建立受控解析与来源绑定”。
- `LiveBlocked`：本版本不可运行，显示缺少的真实设备门禁条件。

### 唯一主路径

`01 入口 → 02 场景/对象 → 03 模板 → 04 准备与预检 → 05 参数草稿 → 06 LOC Mock 参考 → 07 定位规划 → 08 参数快照与运行前确认 → 09 Mock 执行 → 10 Mock 处理 → 11 Mock 结果与 QC → 12 结果包 → 13 只读历史`

- 01–12 是主流程；13 只能从 12 进入并可返回 12。
- 默认协议链为 `LOC → FSE A`；只有用户主动添加时出现 `FSE B`。
- 任一成功页必须由同一 `runId` 的合法状态转换到达，不能通过直接跳页伪造成功。

### 状态与空态

- 运行状态：`Empty / Prepared / Running / Paused / Cancelled / Processing / Reconstructed / QcReady / Packaged / Failed`。
- `Empty`、`Prepared`、`Running`、`Paused`、`Cancelled`、`Failed` 不得显示重建图或 QC 数值。
- 只有 `Reconstructed` 后可以读取重建图；只有 QC 实际计算成功后进入 `QcReady` 并显示数值。
- `Cancelled` 保留 run ID、snapshot ID 和审计事件，不生成成功结果包。
- 本版本不实现应用重启后的运行恢复；该能力当前阶段标记为 `DESIGNED`，对应验收阈值类型为 `PROPOSED`，不影响 v0.1 Mock 闭环验收。

### 参数与身份

- 每次开始 Mock 前生成唯一 `runId` 并冻结唯一 `snapshotId`。
- 快照至少包含场景、对象、模板、协议链、方向、FOV、矩阵、TR、TE 和数据源。
- 开始后修改界面字段不会改变本次冻结快照；再次运行必须生成新的 run ID 与 snapshot ID。

### 结果包

默认根目录为 `%USERPROFILE%\Documents\ScenarioNmr\MockRuns`；测试通过依赖注入使用临时目录。

每个成功结果包目录名包含唯一 run ID，且不得覆盖已有目录。至少包含：

1. `manifest.json`
2. `parameter-snapshot.json`
3. `mock-source.json`
4. `standard-mock-result.png`
5. `mock-qc.json`
6. `audit-events.json`
7. `task-note.txt`

`manifest.json` 必须包含 `dataSource=MOCK`、`softwareCommit`、`runId`、`snapshotId`，并为每个工件记录相对路径、字节数和 SHA-256。manifest 自身不递归记录自己的哈希。

### 人机边界

- 软件负责：确定性状态转换、门禁、唯一身份、Mock 处理、图像级只读 QC、工件封存和可追溯历史。
- 人负责：确认任务语义、样品与协议是否符合科研目的、解释 QC、未来现场安全和真实 Run 单次授权。
- AI 不自动替代科研结论，不把 Mock QC 解释为临床或设备性能结论。

## 5. 成功指标

| 指标 | 通过条件 |
|---|---|
| 主路径完成率 | 一次全新启动可从 01 到 12 完成一条 Mock 路径并从 12 打开 13 后返回 |
| 交互可观察性 | 100% 可见且 enabled 的交互控件产生页面、状态、数据、进度或提示变化 |
| 空态真实性 | 非成功状态的重建图与 QC 数值均为空 |
| 来源一致性 | UI、审计和 manifest 的数据源全部为 `MOCK` |
| 身份唯一性 | 两次运行的 run ID、snapshot ID 和结果包目录均不同 |
| 不覆盖 | 已存在结果包不得被覆盖或静默修改 |
| 工件完整性 | 结果包七项齐全，manifest 中六个外部工件路径、大小与 SHA-256 全部匹配 |
| 设备副作用 | 无参数启动与 Mock 流程的真实 SDK 加载、连接、Run、Abort、eggcontrollerV2 调用次数均为 0 |

## 6. 支持环境

### 支持

- Windows 10/11 x64。
- Qt 6 Widgets，MSYS2 UCRT64/GCC 现有工具链。
- 本地可写 NTFS 用户文档目录或测试注入的临时目录。
- 单用户、单进程、单个前台 Mock 运行。

### 不支持

- 真实设备采集与真实设备恢复。
- 历史 RAW 解析或把历史文件当作新运行输入。
- 多进程并发写同一结果根目录。
- 网络盘、离线同步、云端结果包。
- 临床诊断、患者数据或法规声明。

## 7. 模块、接口与数据流

| 模块 | 输入 | 输出 | 责任 |
|---|---|---|---|
| `MainWindow` | 用户事件、模型快照、结果包摘要 | 可见页面、按钮状态、反馈 | 只编排 UI，不自行推断运行成功 |
| `MockWorkflow` | 数据源、参数草稿、开始/暂停/继续/取消/处理动作 | 状态、run ID、snapshot、审计事件、阻塞原因 | 状态真值与合法转换 |
| `ImageQualityEvaluator` | 本次 Mock 重建图 | SNR、均匀性、对象尺寸或错误 | 只读图像级 QC |
| `MockResultPackage` | 完成的工作流快照、Mock 图、QC、审计、任务说明 | 非覆盖目录、manifest、工件摘要 | 原子化封存与哈希 |
| 历史结果读取 | 结果根目录下有效 manifest | 只读历史行与来源摘要 | 只展示实际封存包，不生成样例行 |
| `DeviceBridge/MriSdkLoader` | 既有显式测试或运维入口 | 既有 fake-SDK 回归 | 不属于 v0.1 可见主流程验收能力 |

数据流：

`用户选择 → 参数草稿 → 冻结 snapshot → MockWorkflow → 现有 Mock 图资产 → ImageQualityEvaluator → MockResultPackage → manifest → 历史只读视图`

## 8. 风险门

### 真实设备未来门禁

未来 Live 必须同时具备以下已证实条件，否则统一 `BLOCKED`：

1. SDK 文件身份和版本已验证。
2. 设备身份明确且 ScanStatus 为 IDLE。
3. 协议、横断位方向和设备参数映射已验证。
4. 参数快照已冻结。
5. 隔离输出目录可写且扫描前基线已记录。
6. 当前进程是唯一 Run owner。
7. 现场人员对本次唯一 Run 明确授权。

本版本不实现这些副作用，只显示逐项缺失原因。

### 产品风险

- Mock 资产与真实设备无关联：界面和包内持续标记 `MOCK`。
- 页面可被测试直接打开：成功数据仍必须服从模型状态，直接打开只显示 Empty。
- 结果目录冲突：拒绝写入，不覆盖。
- QC 计算失败：状态进入 Failed，界面清空图像与 QC，不生成完整成功包；审计事件保留失败原因。

## 9. 发布边界与能力阶段

每项能力只使用一个当前阶段标签：

| 能力 | 当前阶段 | 证据边界 |
|---|---|---|
| 三栏 01–13 视觉结构 | `TESTED` | 既有 QtTest 与视觉 QA；本轮仍需新鲜复验 |
| 持久返回/下一步导航 | `IMPLEMENTED` | 已有代码与历史测试，本轮交互审计尚未完成 |
| 逐控件可观察反馈 | `IMPLEMENTED` | 旧审计仅作候选，本轮证据尚未生成 |
| 确定性 Mock 状态模型 | `DESIGNED` | 本合同 |
| 唯一 run ID 与冻结 snapshot | `DESIGNED` | 本合同 |
| 暂停、继续、取消语义 | `DESIGNED` | 本合同 |
| Mock 重建后图像级 QC | `DESIGNED` | 本合同 |
| 非覆盖结果包与 manifest | `DESIGNED` | 本合同 |
| 历史页读取实际封存结果 | `DESIGNED` | 本合同 |
| HistoricalRaw 执行 | `DESIGNED` | 仅定义 BLOCKED 文案，不实现执行 |
| Live 真实设备执行 | `DESIGNED` | 仅定义 BLOCKED 门禁，不实现副作用 |
| 应用重启后恢复运行 | `DESIGNED` | v0.1 不实现；对应验收阈值类型为 `PROPOSED`，不是发布门 |

说明：能力阶段只使用表头规定的五种标签；`PROPOSED` 只作为验收阈值类型。所有纳入本版本验收的条目在最终放行前必须至少达到 `TESTED`。`TARGET-ENV-VERIFIED` 和 `RELEASE-GATE-PASSED` 只能由本次 Windows 运行证据与完整发布验收推进。
