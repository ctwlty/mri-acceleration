# eggcontrollerV2 自动化流程 Qt 代理设计

## 1. 目标

在现有“场景化核磁共振控制台”中增加“自动化基线模式”，由 `eggcontrollerV2` 的已验证完整入口独占一次扫描、RAW 处理、K-space 中间图生成、最终图生成和图像显示数据生产。Qt 不重写重建算法，不调用替代脚本，也不在同一次任务中自行调用 SDK `Run`。

闭环完成条件不是 Run 成功或 RAW 存在，而是同一次任务同时满足：

1. `eggcontrollerV2` 完整入口正常返回；
2. 本次 RAW 已写盘；
3. 本次 K-space 中间图已写盘并可加载；
4. 本次最终图已写盘并可加载；
5. 两张图均已在场景化控制台中可见；
6. Qt 回到 Ready，且没有启动第二次扫描。

## 2. 唯一行为基线

唯一行为基线为：

`MainWindow_V3.Ui_MainWindow.samplingBtn_click_sync()`

它内部继续使用现有 `HCController`、`consolev3`、SDK、RAW 处理、图像生成和保存逻辑。代理层只负责调用该入口、观察其现有输出路径并把结果返回 Qt；不拆分、不复制、不翻译其内部算法。

以下入口不用于首版代理：离线重建脚本、独立测试脚本、Qt 原生重建实现或其他替代调用顺序。

## 3. 方案比较

### 方案 A：代理完整已验证入口（采用）

Qt 通过 `QProcess` 启动一个极薄的 Python 代理。代理在 `eggcontrollerV2` 根目录中创建必要的 PyQt 应用对象，实例化 `Ui_MainWindow`，关闭 Demo，直接调用 `samplingBtn_click_sync()`，然后从该对象的现有结果字段取得本次 K-space 图和最终图路径，以单行 JSON 返回。

优点：严格复用已验证入口；扫描与重建只有一个所有者；不复制算法。缺点：运行时需要现有 `mri` Python 环境和完整 `eggcontrollerV2`。

### 方案 B：Qt 扫描后调用 RAW 离线脚本（拒绝）

它会改变已验证顺序，且现有离线入口未证明能生成与自动化程序一致的图像。

### 方案 C：把 Python 算法翻译为 C++（拒绝）

它属于重新实现算法，违反唯一行为基线和首版硬门。

## 4. 组件边界

### 4.1 `EggControllerProcess`

新增 Qt 侧进程代理类，只负责：

- 保存 Python 解释器和 `eggcontrollerV2` 根目录配置；
- 以 `QProcess` 启动仓库内的薄代理脚本；
- 读取结构化阶段事件和最终结果；
- 验证返回路径属于本次任务且文件可读、非空；
- 暴露 `starting`、`scanning`、`raw-ready`、`kspace-ready`、`image-ready`、`completed`、`failed` 信号；
- 进程异常退出时报告失败，不自动重启，不触发第二次扫描。

它不加载 `mridll.dll`，不调用 SDK，不解析 RAW，不处理 K-space，不生成图像。

### 4.2 Python 薄代理

薄代理只负责：

- 将工作目录切到用户明确配置的 `eggcontrollerV2` 根目录；
- 导入 `MainWindow_V3.Ui_MainWindow`；
- 创建实例并设置真实模式；
- 调用一次 `samplingBtn_click_sync()`；
- 读取该次记录已有的 RAW、K-space 图和最终图路径；
- 输出 JSON 事件并退出。

薄代理不得包含 FFT、RAW 解析、SDK 状态机或备用重建路径。

### 4.3 场景化控制台

现有界面保留。在“自动化基线模式”下：

- Qt 直接 SDK Run 路径被禁用；
- 开始按钮只启动一次 `EggControllerProcess`；
- 状态区显示代理阶段；
- “中间过程”视口显示本次 K-space PNG；
- “最终图像”视口显示本次最终 PNG；
- 日志显示绝对路径、大小、时间和 SHA-256；
- 只有两张图成功加载到控件后才显示完成。

## 5. 数据流

1. 用户在 Qt 选择“自动化基线模式”并点击开始。
2. Qt 确认没有正在运行的代理任务，且未占用直接 SDK 扫描会话。
3. Qt 启动薄代理，传入 Python 路径和 `eggcontrollerV2` 根目录。
4. 薄代理直接调用一次 `samplingBtn_click_sync()`。
5. `eggcontrollerV2` 按其原流程完成扫描并保存 RAW、K-space PNG、最终 PNG。
6. 薄代理返回同次任务的三个绝对路径。
7. Qt 验证文件并加载两张 PNG。
8. Qt 记录证据并回到 Ready；不自动启动下一次任务。

## 6. 错误处理

- Python、项目根目录、入口导入或依赖缺失：开始前失败，不调用扫描。
- 代理进程异常退出：任务失败，不自动重启。
- `eggcontrollerV2` 报错：原样返回关键错误文本，不进入替代路径。
- 缺少 RAW、K-space 图或最终图：闭环失败，即使扫描已完成。
- 图片存在但 Qt 无法解码或显示：闭环失败。
- 用户主动停止：首版不映射为新的 SDK Abort 逻辑；仅遵守已验证入口自己的处理行为。
- 任意失败后必须由用户再次明确点击才能开始下一次任务。

## 7. 测试设计

先写失败测试，再实施：

1. 自动化模式开始时不调用 Qt 的 `MriSdkLoader::Run`。
2. 代理命令包含配置的 Python、项目根目录和薄代理脚本。
3. 只收到 RAW 时不得完成。
4. 收到 RAW 和单张图时不得完成。
5. 同次 RAW、K-space 图、最终图均存在且两张图成功加载后才完成。
6. 代理异常退出、路径不存在、零字节文件、不可解码图片均失败且不重试。
7. 完成后开始按钮恢复，但不会自动启动第二个进程。
8. 现有 SDK 加载、自动建链、HOLD、DRY_RUN 和扫描生命周期测试继续通过。

测试使用假的代理进程输出和测试 PNG；测试不得连接真实设备。实机验收只在全量测试和 Release 烟测通过后执行一次。

## 8. 实机验收

1. 关闭其他可能占用设备的扫描进程。
2. 可见启动隔离 Release Qt 控制台。
3. 选择自动化基线模式，确认 Qt 直接 Run 未启用。
4. 点击一次开始，记录代理阶段和单次进程启动。
5. 保留本次 RAW、K-space 图和最终图。
6. 在 Qt 中同时显示 K-space 中间图和最终图。
7. 记录三个文件的绝对路径、大小、时间和 SHA-256。
8. Qt 返回 Ready 后停止，不执行第二次扫描。

## 9. SDK 直连与 eggcontrollerV2 代理的区别

- SDK 直连：Qt 自己加载 DLL、配置参数、调用 Run、轮询状态并确认 RAW；它只覆盖设备控制和数据落盘。
- eggcontrollerV2 代理：Qt 不拥有本次 SDK 扫描；完整扫描、RAW 处理和图像生产由已验证自动化入口负责，Qt 只监督进程并显示产物。
- 首版闭环使用代理模式，因为它是当前唯一已证实能从一次真实扫描走到可见图像的行为基线。
