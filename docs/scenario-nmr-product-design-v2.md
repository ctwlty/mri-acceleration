# 场景化核磁共振产品设计 V2

## 1. 设计目标

本版本把产品重心从“让用户选择序列和参数”调整为“让用户从科研任务出发”。用户首屏只需要选择一级场景和检测对象，系统推荐任务模板，再把模板展开为可执行实验链。

核心路径：

```text
一级场景 + 检测对象 -> 推荐任务模板 -> 展开实验链 -> 图像质控 -> 结果交接
```

## 2. 产品边界

- 本控制台负责生成实验模板、获得图像、完成图像质控并交接结果。
- 血管分割、脂肪/水分/油分定量、糖度预测和 fMRI 统计由外部分析软件完成。
- 预设参数可使用通用参考值，但必须标记为“待设备适配”。
- 设备连接和采集验收完成前，真实 `Run()` 保持 HOLD。
- 已跑通基础序列继续称为 `FSE A` 和 `FSE B`，未核验前不命名为 T1 或 T2。

## 3. 用户角色

| 角色 | 主要诉求 | 设计响应 |
| --- | --- | --- |
| 科研人员 | 复用实验流程，保证样品、协议、质控和交接信息完整 | 模板推荐、实验链记录、QC 报告、外部软件交接包 |
| 教学老师 | 快速演示科研任务如何从目标进入扫描流程 | 低门槛首屏、清晰步骤条、Demo 模式 |
| 设备操作员 | 降低误操作，明确何时能采集、何时被 HOLD | 状态门禁、预检清单、Run HOLD 标签 |
| 方法开发者 | 后续补齐协议参数和处理算法 | 模板内参数抽屉、设备适配状态、版本记录 |

## 4. 信息架构

### 4.1 一级导航

| 导航 | 目的 |
| --- | --- |
| 任务推荐 | 从一级场景和检测对象得到任务模板 |
| 实验执行 | 展开模板并按步骤完成准备、定位、采集和重建 |
| 图像质控 | 查看通用 QC、任务特异 QC 和异常建议 |
| 结果交接 | 生成图像、协议、元数据、QC 记录和外部软件输入包 |
| 模板库 | 管理任务模板、协议版本和设备适配状态 |

### 4.2 首屏推荐区

首屏只展示两个主要输入：

- 一级场景：结构与形态成像、参数与成分定量、品质与性状预测、动态与功能成像。
- 检测对象：按样品/动物/组织/部位管理，不作为一级场景。

序列、协议和参数不出现在首屏推荐条件中，只在任务模板详情和高级抽屉里展示。

## 5. 核心用户流

### 5.1 推荐任务模板

1. 用户选择一级场景。
2. 用户选择检测对象。
3. 系统展示推荐任务模板卡片。
4. 用户查看模板适配状态、输出类型、预计步骤和限制说明。
5. 用户选择一个模板进入实验链。

推荐卡片必须显示：

- 推荐任务模板名称
- 典型输出
- 适配状态：Demo / 待设备适配 / 已设备适配
- Run 状态：HOLD / 可采集
- 输出交接目标：图像、参数图、模型输入、4D 时序等
- 关键风险：运动、ROI 覆盖、参考真值、同步信号等

### 5.2 展开实验链

模板展开为固定四段：

1. 获取图像 / 采集协议
2. 准备与预检
3. 定位与采集
4. 处理与重建

每段用步骤清单呈现，步骤状态包括：

- 未开始
- 进行中
- 已通过
- 需确认
- 阻断
- 跳过

### 5.3 图像质控

采集或 Demo 结果进入 QC 工作台，默认展示通用图像质控：

- SNR
- 均匀性
- 几何畸变 / 尺寸准确性
- 空间分辨率
- 伪影
- 重复扫描稳定性

标准模体由软件自动判定；科研样品由软件提示指标与异常，最终由科研用户确认。

### 5.4 结果交接

质控完成后生成交接包：

- 图像或重建结果
- 原始数据索引
- 任务模板版本
- 采集协议版本
- 样品和对象元数据
- QC 记录
- 外部分析软件所需输入文件

交接动作不代表完成最终科研分析，只代表控制台已完成“图像获得 + 质控 + 数据整理”。

## 6. 页面设计

### 6.1 任务推荐页

布局建议：

- 左侧窄栏：一级场景选择，使用四个固定分类。
- 中部主区：检测对象选择和推荐模板卡片。
- 右侧详情：当前选择的任务模板摘要、输出、风险和边界。
- 底部状态：设备连接、SDK 模式、Run 状态、参数适配状态。

关键交互：

- 选择一级场景后，检测对象列表按相关性排序。
- 选择检测对象后，模板卡片即时刷新。
- 模板卡片不显示底层参数，只显示协议类型和适配状态。
- `Run HOLD` 用明确状态条提示，不用隐藏在日志里。

### 6.2 任务模板详情页

内容结构：

- 任务目标：本模板要获得什么科研输出。
- 适用对象：样品、动物、组织或部位。
- 实验链：四个固定模块。
- 输出物：图像、参数图、模型输入、4D 时序、QC 记录。
- 边界说明：哪些结果交给外部软件完成。
- 高级抽屉：序列、参数、协议文件、设备适配说明。

高级抽屉默认收起，并且所有未核验字段带“待设备适配”标签。

### 6.3 实验执行页

布局建议：

- 顶部：任务名、对象、模板版本、Run 状态。
- 左侧：实验链步骤导航。
- 中间：当前步骤操作区。
- 右侧：设备状态、预检结果、图像预览或定位图。
- 底部：日志、异常、保存路径和下一步按钮。

执行门禁：

- 设备未连接时，不允许进入采集。
- 预检未完成时，不允许真实 Run。
- 模板为“待设备适配”时，真实 Run 保持 HOLD。
- Demo 模式可走完整 UI 流程，但必须清楚标注 Demo。

### 6.4 图像质控页

布局建议：

- 中部：图像查看器或多视图网格。
- 右侧：QC 指标、阈值、判定和异常建议。
- 底部：重复扫描对比、用户确认、生成交接包。

QC 判定分为：

- 自动通过：仅限标准模体和已验证规则。
- 需用户确认：科研样品默认状态。
- 不通过：关键指标低于阈值或存在阻断异常。

### 6.5 结果交接页

布局建议：

- 左侧：本次实验摘要。
- 中部：输出文件清单。
- 右侧：外部分析软件交接说明。
- 底部：导出、打开结果目录、生成报告。

首版输出不需要直接集成外部分析软件，先做标准化文件夹和元数据清单。

| --- | --- | --- | --- | --- | --- | --- | --- |

| 参数与成分定量 | 单粒或批量种子 | 种子水分 / 油分定量数据采集模板 | 组成敏感图像、弛豫或频谱候选协议 | 记录品种、批次、质量、温度和装样方式 | 确认样品区域并按模板重复采集 | 图像/信号解析和特征提取 | 输出特征、样品信息、真值编号和 QC；最终定量需标定验证 |
| 品质与性状预测 | 水果整体或指定果肉区域 | 水果糖度预测数据采集模板 | 定位 + 标准化多对比候选采集 | 记录品种、成熟度、温度并绑定糖度真值 | 固定摆位，确认覆盖并标准化采集 | 重建、ROI/特征提取和数据标准化 | 输出模型输入和 QC；糖度由外部模型预测 |
| 动态与功能成像 | 小鼠脑 | 小鼠脑 fMRI 模板 | 定位 + 解剖参考 + 快速功能时序 | 检查固定、生理状态、刺激范式和同步条件 | 确认脑区覆盖并记录刺激和时间戳 | 4D 重建及基础运动、漂移检查 | 输出 4D 时序、解剖参考、事件日志和 QC；功能分区交外部软件 |

## 8. 模板数据结构

建议把任务模板拆成以下对象：

| 对象 | 字段示例 |
| --- | --- |
| ResearchScene | `id`, `name`, `researchGoal`, `typicalOutputs`, `description` |
| DetectionObject | `id`, `name`, `category`, `precheckMetadata`, `positioningHints` |
| TaskTemplate | `id`, `sceneId`, `objectIds`, `name`, `outputType`, `adaptationStatus`, `runGate`, `riskTags` |
| ExperimentModule | `templateId`, `moduleType`, `steps`, `requiredInputs`, `blockingChecks` |
| AcquisitionProtocol | `templateId`, `protocolName`, `sequenceAlias`, `parameterStatus`, `parameterProfileRef` |
| QcProfile | `templateId`, `metrics`, `thresholds`, `autoJudgeMode`, `reviewPolicy` |
| HandoffPackage | `scanRecordId`, `files`, `metadata`, `qcReport`, `externalAnalysisTarget` |

## 9. 参数预设设计

0.17 T 参数预设作为任务模板内部资产，不作为首屏推荐条件。详情见 `docs/scenario-nmr-017t-parameter-presets.md`。

参数预设在产品中按以下规则进入模板：

- 每个任务模板可绑定一个或多个协议预设，例如 `LOC_017T`、`FSE_A_017T`、`FSE_B_017T`、`MEGRE_PHASE_017T`。
- 参数预设版本统一显示为 `presetVersion=2`。
- 所有 0.17 T 参数预设在完成实机验证前，状态固定为“待设备适配”。
- `Run HOLD` 和参数适配状态必须同时显示，不能只在日志里提示。
- 目标重建矩阵和 SDK 底层采样字段分开展示，避免把 `noSamples / noViews` 直接等同于目标矩阵。
- `FSE A / FSE B` 的 `12.9 ms` 只显示为“序列标称 TE”，不能写成“有效 TE”。

模板详情页中的参数预设区建议分三层：

| 层级 | 默认状态 | 展示内容 |
| --- | --- | --- |
| 协议摘要 | 展开 | 协议别名、用途、适配状态、Run 状态 |
| 关键参数 | 展开 | TR、TE、FOV、矩阵、层厚、层数、NEX 等科研用户需要复核的字段 |
| SDK 映射 | 收起 | 底层字段、参数文件、序列字段映射、回填状态 |

导出交接包时必须携带：

- `presetVersion`
- 协议别名
- 参数适配状态
- Run 状态
- 物理边界检查结论
- 未回填字段清单

## 10. UI 文案规范

- 使用“一级场景”，不要使用“行业场景”。
- 使用“检测对象”，不要把小鼠、根茎、生蚝、种子、水果放进一级场景。
- 使用“推荐任务模板”，不要在首屏说“推荐序列”。
- 使用“FSE A / FSE B”，未核验前不写 T1 / T2。
- 使用“待设备适配”，不要写“已验证参数”。
- 使用“Run HOLD”，让真实采集边界显性化。
- 使用“序列标称 TE”，不要把未核验的 `12.9 ms` 写成“有效 TE”。
- 使用“目标重建矩阵”，不要把它直接等同于 SDK 底层采样字段。

## 11. MVP 范围

首版建议只实现这些内容：

- 一级场景与检测对象选择。
- 推荐任务模板列表。
- 模板详情与四段实验链。
- Demo 模式实验执行。
- 通用图像质控指标展示。
- 结果交接包清单。
- 模板、协议和参数的“待设备适配”标签。
- 真实 Run HOLD 门禁。
- 0.17 T 参数预设只在模板详情页和导出报告中展示，不进入首屏推荐条件。

暂不做：

- 外部分析软件深度集成。
- 临床工作流。
- 参数自动优化。
- 未验证协议的真实采集。
- 直接宣称脂肪、水分、糖度或 fMRI 统计结果。
- 自动把目标矩阵换算成 SDK 底层 `noSamples / noViews` 字段。

## 12. 设计验收标准

- 首屏没有要求用户选择序列或参数。
- 用户选择一级场景和检测对象后，能看到推荐任务模板。
- 任务模板能展开为四个固定模块。
- 每个模板都有适配状态和 Run 状态。
- 图像质控与结果交接是独立阶段。
- 未验证参数和协议全部带“待设备适配”标签。
- 文案不暗示临床诊断能力。
- Demo 模式和真实 SDK 模式在界面上可区分。
- 参数预设能显示 `presetVersion=2`、协议别名、适配状态和 Run 状态。
- `FSE A / FSE B` 的 `12.9 ms` 展示为“序列标称 TE”。

## 13. 后续进入开发前的待确认项

- 每个任务模板的真实协议文件和参数文件来源。
- `FSE A` 和 `FSE B` 的设备适配状态。
- 标准模体 QC 阈值。
- 科研样品 QC 是否只提示异常，还是允许用户配置阈值。
- 交接包文件夹结构和外部分析软件的输入格式。
- 当前序列到 SDK 字段的映射。
- 实际最短 TE、梯度爬升、RF 功率和均匀成像区。
