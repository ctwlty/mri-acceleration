# 场景化核磁共振客户端技术设计

## 1. 目标

将谱仪 DLL 暴露的硬件控制能力，封装为一个面向科研与教学的 Windows 桌面客户端。客户端优先采用 Qt/C++ 实现，保持可视化层美观、稳定、可扩展，同时保留未来切换到 MFC 的可行性。

## 2. 产品边界

- 只覆盖科研与教学。
- 不做临床诊断工作流。
- 不做固件层改造。
- 不把底层 DLL 参数直接暴露给普通用户。

## 3. 设计原则

- 场景优先：先选场景，再选对象、序列和操作。
- 模板优先：常见实验做成模板包，不让用户反复配参数。
- 状态可见：连接、通道、温度、异常、扫描进度都要可见。
- 风格克制：以浅灰、蓝、墨黑为主，强调设备控制感，不做营销风。
- 复杂度隐藏：底层 DLL 细节放进向导和高级抽屉面板。

## 4. 推荐技术栈

- 桌面框架：Qt Widgets。
- UI 设计方式：Qt Designer + 代码定制。
- 数据组织：Model/View 方式管理场景列表、模板列表、日志和结果表。
- 主题方式：QStyle / stylesheet 局部定制，避免过度花哨。
- 原型承接：静态 HTML 原型仅用于产品沟通，真实客户端对齐该结构。

Qt 的布局系统适合保证窗口缩放时控件自动排布，Qt Widgets Designer 也适合以可视化方式搭建窗口，再用信号槽接入业务逻辑。Qt 的 model/view 架构适合承载场景模板、采集记录和结果列表等密集信息。

## 5. 信息架构

### 左侧控制栏

- 场景模板
- 检测对象
- 序列选择
- 中间操作 A/B
- 图像处理
- 分析指标
- 一键建链、校准向导、开始采集、暂停、急停

### 中间工作区

- 当前工作流条
- 参数确认表单
- 扫描预览区
- 序列/通道状态提示

### 右侧观察区

- 2x2 图像或波形窗口
- 重建结果
- 结果对照
- 通道/导航状态

### 底部状态区

- 运行日志
- 温度/连接/异常
- SNR、均匀性、峰值、面积等指标
- 保存与导出状态

## 6. 页面与组件

### 6.1 主窗口

- 顶栏：产品名、设备连接状态、传输模式、当前场景。
- 左栏：模板列表 + 模板参数摘要 + 主操作按钮。
- 主区：工作流条 + 影像区。
- 底栏：指标卡 + 日志 + 异常提示。

### 6.2 场景模板面板

- 支持搜索、分类、收藏、最近使用。
- 模板卡片展示场景、对象、序列、默认指标。
- 支持双击进入编辑或执行。

### 6.3 校准向导

- 连接检查
- 系统信息读取
- 通道配置
- 中心频率与匀场
- 预加重和滤波
- 预检通过后允许 Run

### 6.4 采集状态面板

- Scanstatus / ScanCompleted
- 当前扫描号 / 总扫描号
- 温度
- 异常位
- 回调节奏和数据接收提示

### 6.5 结果面板

- 原始数据缩略图
- 重建结果
- ROI 统计
- 指标曲线
- 导出按钮

## 7. 技术分层

### 7.1 UI 层

负责布局、控件状态、主题和交互反馈。

### 7.2 应用编排层

负责把“场景模板”展开成一组控制动作，管理步骤流转和错误回退。

### 7.3 设备适配层

负责封装 DLL 接口，统一初始化、参数配置、扫描控制、回调和异常信息。

### 7.4 数据层

负责模板、日志、结果文件、最近项目和用户偏好设置。

## 8. 关键对象

- SceneTemplate：场景模板。
- ObjectProfile：检测对象描述。
- SequenceProfile：序列选择与参数包。
- ActionStep：中间操作步骤。
- ImageProcessProfile：图像处理配置。
- AnalysisMetric：分析指标定义。
- DeviceSession：设备连接状态。
- ScanRecord：一次扫描记录。

## 9. 与 DLL 的映射

- Init / ConfigFile -> 建链与硬件预检。
- SetSystemSel / SetCenterFre / SetTotalCh / SetChSel -> 模板系统配置。
- SetParameterFile / SetParameter -> 序列模板与参数包。
- PrepareRun / Run / SetupModeRun -> 采集执行。
- Scanstatus / ScanCompleted / GetAbnormalStatus -> 状态同步。
- RegisterDataRecv / RegisterImageP -> 数据回调与图像更新。
- SaveSystemFile / SetRecvMode / HighSpeedModeConnect -> 系统保存与传输模式。

## 10. UI 美观性要求

- 左栏固定节奏，不要过密也不要过松。
- 主区必须有稳定网格，不能随窗口变化跳动。
- 状态色只用于明确反馈，不做大面积装饰。
- 指标卡与日志区要有足够留白，避免“信息墙”压迫感。
- 主按钮层级必须清晰：建链、采集、暂停、急停一眼可辨。
- 任何长文本都应截断或换行，不能挤坏布局。

## 11. 实施建议

1. 先做 Qt Widgets 主窗口骨架。
2. 用 QSplitter 或网格布局固定三栏结构。
3. 左栏模板列表和右侧结果区用 model/view 管理。
4. 用信号槽把场景选择和模板展开串起来。
5. 先实现可读的状态面板，再接设备 DLL。

## 12. 下一步

如果继续开发，优先顺序是：

1. 真实序列编程手册补齐字段映射。
2. 设备控制状态机落地。
3. Qt 主窗口和主题系统实现。
4. 模板导入导出和扫描记录持久化。
